# 11월 20일 CAMT AI 브리핑 첫 공개 계획

**완료 기준**은 11월 20일(금) 18시 KST까지 비로그인 방문자가 공개 웹의 CAMT 상세에서 실제 SEC 공시를 요약한 한국어 브리핑 한 건을 읽고 인용 링크로 원문을 여는 것이다. 첫 공개 범위는 CAMT 한 종목, 운영자가 원문과 대조해 승인한 AI 초안 한 건으로 잡는다.

Java main에는 SEC 수집, 시점별 검색, 초안 생성·승인 서비스가 있다. 공개 GET은 Python Gateway를 읽고, React에는 이미 [패널](../src/features/briefing/BriefingPanel.tsx)과 [응답 파서](../src/features/briefing/schemas.ts)가 있다. Gemini는 이번 [Java #33](https://github.com/AnDev77/doChallenge/pull/33)에서 추가한 선택지이며 실제 응답은 미검증이다.

|---|---|---|

**응답 계약.** `GET /api/v1/briefings/CAMT?window=7d`에서 승인된 한글 요약을 웹의 `summary[]`와 문자열 `citation_ids`에 매핑한다. 현 파서는 요약 1~3개, 항목당 1,000자까지 받으므로 첫 초안은 인용을 확인한 1,000자 이내 요약 한 개로 검토한다. 각 인용에 고유 ID, 출처명, HTTPS 원문 URL, 접수 시각을 보낸다. 방향 판단은 `withheld`, 분석하지 않은 요인 배열은 비워 둔다. 생성 시각과 자료 기준 시각은 구분하고, 저장된 시각을 기준으로 최신 여부를 판정한다.

**일정이 막힐 때.** Gemini 키가 준비되지 않으면 사용 가능한 기존 OpenAI 설정과 호출 예산을 확인해 같은 경로로 생성한다. 최근 7일에 적격 공시가 없으면 실제 과거 CAMT 공시로 기준일을 고정해 생성하고, 화면과 API에 해당 기간을 명시한 ‘과거 공시 브리핑’으로 공개하는 범위로 조정한다. 과거 기준일에는 그때까지 수집된 자료만 사용한다. 과거 수집 이력이 없다면 오늘 수집한 과거 공시의 접수일과 오늘의 수집·요약 시각을 명시하는 별도 단건 보기로 제공한다. 현재 7일 조회는 자료 부족을 표시한다. 실 모델 응답이나 배포 경로가 확보되지 않으면 완료 상태는 각각 프론트 통합 또는 프리뷰 검증까지로 기록한다.

Kafka를 통한 자동 생성, 다종목 확대, 모델 30건 비교는 첫 공개 이후 작업이다. 공개 후 러너스하이 기록에는 조회와 생성 분리 및 인용 검증 근거를, 포트폴리오에는 실제로 공개한 URL·동작·검증 범위를 적는다.

## 기존 초안 통합 의존성

2026-11-15 조회에서 웹 #4(채팅 조회 수정), #5(회원별 관심 목록), #6(가입 후 토론방 복귀), #7(SPCX/CAMT 상세)가 열려 있다. Java #16(관심 목록), #17(IP TLS 갱신), #20(배포 진단), #21(EC2 후보 기동), #22(채팅 제한) 등도 열려 있다. 이 기능들은 main에 이미 포함됐다고 가정하지 않는다. 월요일에 각 PR의 실제 기반·중복 변경·필수 선행 PR을 확인하고 필요한 변경을 통합 브랜치에서 시험한 뒤 승인 대상으로 제시한다. #21만 병합하면 공개 운영 배포가 끝나는 것이 아니다. 기존 스키마·Nginx·인증 설정과 공개 전환 경로까지 확인한다. 최신 계획은 이 문서를 유지하고 과거 PR의 일일 계획으로 덮어쓰지 않는다.

## 월요일 해결해야 할 외부 분기

1. Java #21은 마지막 확인에서 초안이며 병합 승인이 아직 없다. 사용자의 자동 병합 금지는 유지한다. 역할/배포 권한·환경 변수 존재를 확인하고 실제로 필요한 승인만 요청한다. 기존 읽기 전용 SSM 성공은 앱 기동 권한 확인이 아니다.
2. LLM·임베딩 제공자의 운영 키와 월 지출 상한. 계정에 설정돼 있는지 우선 확인하고 없을 때만 사용자에게 비밀 저장소 등록을 요청한다. 키는 채팅으로 받지 않는다. 화요일까지 호출 불가면 수요일 실제 AI 요약 목표가 막힌다고 즉시 알린다.
3. 수집 원문의 허용 범위·정상 응답. 뉴스 공급원 미확보 시 공식 공시·IR 소식으로 범위를 명시한다. 독립 출처 부족이면 판단을 보류하며 가짜 근거를 추가하지 않는다.

## 시험과 완료 조건

- 소프트웨어: 웹 check/test/build/dist/routes + 모바일/데스크톱. Java 전체 시험·Redis·JAR. Python wheel·포함 파일·Ruff/Pyright·전체 시험. 마지막 커밋 CI와 실제 운영 인수를 각각 기록.
- 평가: 문서 20개 고정 세트에 종목·시각·핵심 사실·출처·보류 필요 여부를 사람이 지정한다. 출처 ID 유효성 100%, 표본 내 꾸며낸 핵심 사실/수치 0건, 기간/종목 혼입 0건을 출시 기준으로 제안한다. 실패한 범주는 공개 판단을 차단한다. 이는 달성 실적이나 미래 수익률 정확도가 아니다.
- UI: 360px~1440px 가로 넘침 없음, 출처 키보드 접근, 생성 도중 이탈/재접속 복구. 참고 문서를 복제한 모의 화면과 실서비스 인수를 구분한다.
- 운영 목표(실측 전): 캐시 응답 p95 1초 이내, 생성 완료 p95 30초 이내·60초 제한, 동시 생성 1건부터. 예상 사용자 10명 동시 조회로 API·큐·메모리·비용 측정 후 조정. 달성하지 못하면 실제 값을 기록.
- 장애: LLM 429/timeout, 수집 실패, 잘못된 JSON/인용, worker 종료, Redis 장애, DB 재접속, Nginx 전환 실패를 검증. MySQL 볼륨 삭제 금지, 추가 스키마만 먼저 적용, 이전 Java 이미지와 공존 확인.

## 범위 절감 순서

해외 시장 전체, 실시간 일괄 시세, 전 종목 AI, 자유 질문, 자동 알림, 월가 목표가와 추가 토론방을 뒤로 미룬다. 미국 종목 검색은 목록 사용 범위와 데이터 검증이 완료된 후 추가한다. 핵심 '실자료 검색→요약→출처→근거 판단'을 가짜 응답으로 대체하지 않는다. 첫 배포에서 처리하지 못한 종목과 기능은 미지원으로 구분한다.
