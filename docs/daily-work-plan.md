# 최신 일일 작업 계획과 완료 기준

갱신일: 2026-10-29 한국 시간. 사용자의 최신 결정과 [중간 평가](reviews/project-midpoint-review-2026-10-29.md)를 반영한다. 이 문서는 현재 작업의 진입점이며 이전 기능 리뷰는 근거 이력이다.

## 앞으로의 작업 시작 절차

1. 세 저장소의 main과 열린 PR, 현재 작업 트리 변경을 확인한다. 다른 실행의 변경을 먼저 동기화하고 덮어쓰지 않는다.
2. 최신 사용자 결정→이 문서→최신 중간 평가→해당 저장소 AGENTS·기능 리뷰 순서로 범위를 확인한다. 날짜가 최신인 파일 하나만 보고 기존 핵심 목표를 지우지 않는다.
3. 하루 핵심 기능과 완료 시험, 필요한 외부 입력을 먼저 정한다. 이미 완료한 작은 검사를 반복해 하루 진척으로 세지 않는다. 작업량은 사용자 기능 한 흐름과 오류 처리·시험·리뷰를 포함한다.
4. 일반 구현은 질문 없이 오늘 할당한 범위를 끝까지 수행한다. 외부 입력·운영 설정·배포 승인 등 분기점에서만 질문하며 독립 작업은 계속한다.
5. 시작/중간/완료 증거를 갱신한다. 로컬/원격 시험, 실제 배포, 연구 결과, 사용자 수요를 분리한다. 오래된 PR 성공을 최신 커밋 성공으로 재사용하지 않는다.

## 오늘의 핵심 기능: 인증된 이메일로만 가입

| 단계 | 작업·근거 | 판정 |
|---|---|---|
| 시작 | 기존 Java에 메일 발송·코드 확인 API가 있으나 가입은 이메일별 인증 플래그만 확인 | 개선 대상 확인 |
| 구현 | 확인 성공 시 일회용 가입 증표, Redis 해시 저장·10분 만료, 이메일 결합, 원자적 소진 | Java 초안 PR #7 구현 |
| 중간 | 로컬 Gradle 다운로드가 네트워크에서 차단; JDK 21도 없음 | 로컬 시험 미실행, 원격 Java 21·Redis로 검증 |
| 완료 조건 | 전체 Java 시험·Redis 동시성/만료/재사용 시험·실행 JAR 내용 확인, 원격 PR 게이트, 실패·제약 리뷰 | 코드 `441317c`의 원격 전체 35개 시험 통과(실제 Redis 6개 포함), 실패·생략 0, bootJar·클래스 포함 검사 통과 |

이번 작업의 완료는 이메일 가입의 보안 경계 개선이다. 웹 가입과 실제 메일 수신, 공개 회원 서비스가 모두 완료됐다는 뜻이 아니다. 채팅은 계속 핵심 목표이며 금융 종목방의 저장·권한·재접속으로 이어간다.

## 배포 전 이메일 인증 인수 조건

- [ ] 발송 요청→실제 수신→코드 확인→증표 포함 가입→로그인을 브라우저에서 확인한다.
- [ ] 잘못된/만료된 코드, 인증 전 가입, 다른 이메일 증표, 재사용·동시 요청을 차단한다.
- [ ] 이메일/IP별 재발송·코드 시도 제한과 SMTP timeout/실패 안내를 구현·시험한다.
- [ ] 운영 SMTP 발신 설정·시험 수신처·Redis·회원 DB 연결을 확인한다. 비밀값과 증표는 URL·공개 로그·문서에 남기지 않는다.
- [ ] DB 저장 실패 뒤 소진된 증표의 재인증 안내와 중복 가입 처리, 이메일 정규화 정책을 확인한다.

공개 홈만 제공하는 배포와 가입 가능한 회원 서비스 배포를 구분한다. 위 조건이 없으면 회원 서비스 배포 완료로 표시하지 않는다.

## 이어서 할 작업과 일정 판단

1. 회원 흐름: 인증 시도·재발송 제한, SMTP 설정 확인, React 가입·로그인 연결.
2. 금융 종목방: QQQ/SPY 고정 방, 공개 조회·로그인 쓰기, 저장 후 방송·중복 방지·재접속, 신고·삭제.
3. 관심 목록 Java 소유 확정, 공개 발표 목록/상세 연결, 통합 브라우저 검증.
4. 31일에는 실제 확인된 범위로 첫 화면/내부 시연/공개 베타를 판정한다. 이메일 인증 요구가 추가됐으므로 기존 일정의 전체 완성을 보장하지 않는다.

연구는 수집·실제 결과 확인을 병행하되 검증 전 미래 성능은 HOLD다. Kafka·Jenkins·Blue-Green은 포트폴리오 확장 목표로 유지한다. 노트·결제·주주 인증은 첫 배포 후다.

## 외부 입력과 다음 분기

실메일 시험에 필요한 것은 배포용 SMTP 연결 설정과 발신 주소, 사용자가 지정한 시험 수신처다. 연결 정보는 배포 비밀 저장소로 제공하고 채팅에 비밀번호를 쓰지 않는다. 지금은 실제 수신 성공을 확인하지 않았으며 비밀값을 찾거나 임의 수신자에게 메일을 보내지 않는다. 입력 확인 전에도 가입 증표·재시도·권한의 독립 시험과 화면 연결은 진행할 수 있다.

## 오늘의 종료 근거

[Java 원격 검사](https://github.com/AnDev77/doChallenge/actions/runs/40825591112)에서 코드 `441317c`의 전체 35개 시험과 실행 JAR 검증을 확인했다. 로컬 실패는 해결했다고 기록하지 않는다. 실제 SMTP 수신·웹 가입·남용 방어는 미완료다. Java 기능 변경은 12개 파일(신규 시험 13개 포함)이며, 웹·AI의 개발 기준 문서는 별도 반영했다. 다음 작업은 재발송/시도 제한과 가입 화면 연결이다.

## 오늘 남은 할당량의 구현 기록

- 이메일별 60초/1시간 발송 제한, IP별 인증 요청 제한, 코드 5회 오입력 폐기, Retry-After, SMTP timeout·오류 처리: Java PR #7 구현·원격 게이트 통과.
- React 발송→확인→가입→로그인·로그아웃, 증표 만료·이메일 변경·재인증 안내: 웹 PR #1 구현. 로컬 화면/계약 시험 14개 및 직접 URL 7개 통과.
- 브라우저 검증: 로컬 Chromium 설치 파일 오류로 실행 불가. 원격 CI의 데스크톱·모바일 에뮬레이션에서 합성 API를 사용해 확인한다. 결과는 PR 게이트에 기록한다.
- 실제 SMTP 수신·운영 API 연결: 외부 설정이 필요한 분기점으로 남긴다. [연결 설정과 인수 조건](auth-connection.md)에 필요한 설정만 적었으며 비밀값은 저장하지 않았다.

오늘 코드 할당을 회원 흐름까지 구현했다고 해서 채팅·관심 목록·공개 베타가 완료된 것은 아니다. 다음 핵심 기능은 금융 QQQ/SPY 방의 저장·권한·재접속과 화면 연결이며, 연구 실제 결과 확인도 별도 트랙으로 유지한다.
