# QQQ·SPY 종목방 웹 연결과 첫 배포 판정

기준일: 2026-11-02. 시작 시 웹 main `a2c354e`, 초안 PR #1 `538f883d`를 확인했다. PR #1에는 회원 가입·로그인 화면이 있지만 종목방은 비활성 안내만 있었다. Java PR #8의 최근 30개/`afterId`/JWT POST 계약과 통합 배포 초안 PR #9를 확인했다.

## 구현과 중간 오류

- `src/features/chat/api.ts`는 QQQ·SPY 메시지 계약을 Zod로 확인하고, 공개 읽기와 JWT 쓰기를 분리한다. HTML 200과 다른 종목의 응답은 실패로 취급한다.
- `src/pages/RoomPage.tsx`는 5초 간격의 `afterId` 조회로 새 글과 재접속 누락을 채운다. 글은 저장 응답 뒤에만 목록에 반영한다. 응답이 끊긴 동일 본문 재시도에는 같은 UUID를 사용한다. 기능 플래그가 꺼져 있으면 기존 준비 화면을 유지한다.
- 첫 로컬 정적 검사는 React effect에서 동기 상태 초기화를 지적했다. 종목별 화면을 key로 분리해 상태를 새로 만들고 effect 안의 동기 갱신을 제거했다.

## 검증과 한계

- 로컬 타입·린트, 17개 화면/계약 시험, 빌드, 자산 검사, 직접 URL 7개는 통과했다. 새 시험은 공개 읽기·로그인 쓰기·HTML fallback·다른 종목 응답을 확인한다.
- 로컬 Playwright는 Chromium 실행 파일이 없어 4개 브라우저 시험을 실행하지 못했다. 원격 PR 게이트의 실제 Chromium 결과를 별도로 확인해야 한다.
- 이 첫 웹 화면은 5초 폴링이다. 서버 STOMP 구독의 실제 양방향 지연, 두 브라우저/운영 DB/SMTP/Vercel 변수와 HTTPS 연결은 아직 확인하지 않았다. 신고·삭제·전송 제한과 금융 예측 성능·제품 수요도 미확인이다.
- 승인된 API 호스트가 없으면 `VITE_CHAT_ENABLED`와 `VITE_AUTH_ENABLED`를 켜지 않는다. 토론방이 공개 화면에 보인다는 사실과 이용자 메시지를 실제로 읽고 쓰는 배포 성공을 구분한다.
