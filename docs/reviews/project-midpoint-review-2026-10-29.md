# 프로젝트 방향과 진도 중간 평가

기준일: 2026-10-29 한국 시간. 대상: ShockGraph AI, doChallenge의 금융 전환, shockgraph-web. 공개 가능한 사실과 판단만 기록하며 원본 가격·비밀값·비공개 점수는 포함하지 않는다.

후속 사용자 결정: 매 작업은 [최신 일일 작업 계획](../daily-work-plan.md)을 먼저 읽어 작업량을 정한다. 공개 회원 서비스 배포 전에 회원가입 이메일 인증을 완료한다. 기존 인증 확인과 가입 요청의 연결을 먼저 보강하고 실제 채팅 통합으로 이어간다.

## 결론

두 축의 방향은 유지한다. 첫째는 공식 거시 발표와 QQQ·SPY의 과거 반응을 같은 기준으로 확인하는 자료·분석 기능, 둘째는 해당 종목의 관심 등록과 실제 대화다. 미래 예측은 별도 연구로 병행한다. 연구가 아직 검증되지 않았다는 이유로 채팅을 제거하거나 외부 차트 링크만으로 서비스 목표를 대체하지 않는다.

현재는 수집·검증 기반과 화면 골격이 만들어진 상태다. 사용자가 가입하고 관심 종목을 저장한 뒤 실제 대화를 이어가는 통합 서비스는 완료되지 않았다. 31일 첫 화면 공개는 조건부로 가능하지만, 기존 계획의 금융 커뮤니티 전체와 Blue-Green 복구까지 같은 날 완료된다고 보장할 근거는 부족하다. 완성률의 분모와 작업 난도가 고정돼 있지 않아 임의의 퍼센트로 진도를 표시하지 않는다.

## 반드시 수정할 사항

### 1. 화면 공개와 서비스 완료의 기준 통일 — 최우선

전체 계획에는 가입·관심 목록·실제 채팅이 있지만 웹 문서는 종목방 진입까지만 첫 배포로 적고 있었다. 이번에 웹 AGENTS와 배포 문서의 표현을 수정했다. 앞으로 보고에는 `첫 화면 공개`, `통합 시연`, `공개 베타`를 명시한다. 채팅 준비 화면은 실제 채팅 완료로 세지 않는다.

### 2. 회원 데이터 소유권을 코드로 확정 — 최우선

Java는 회원·관심 목록·종목방을, Python은 공식 자료와 분석을 소유한다. 공개 발표 조회는 사용자 JWT가 꼭 필요한 기능으로 만들지 않는다. FastAPI #11의 관심 목록을 최종 Java 기능과 동시에 운영하며 두 DB에 쓰지 않는다. 실사용 데이터가 없다면 불필요한 운영 이관 도구부터 만들지 않고 신규 Java 경로로 연결한다. 기존 실사용 데이터가 있는지는 먼저 확인하고, 있을 때만 매핑·검증·롤백을 적용한다.

### 3. 다음 구현을 실제 사용자 흐름 한 건에 집중 — 최우선

다음 핵심 개발은 Java 금융 종목방의 최소 흐름이다. QQQ·SPY 고정 방, 공개 조회·로그인 작성, 서버가 결정한 작성자, DB 저장 후 방송, 재접속 시 누락 조회를 함께 구현하고 웹으로 연결한다. 채팅의 메시지 ID와 커서 기준을 고정하고 재전송 시 중복 저장을 막는다. 익명 전송·만료 토큰·다른 작성자 위장·DB 저장 실패 뒤 방송을 거부하는 시험을 포함한다. 공개 전 신고·삭제와 전송 제한을 검증한다. 인프라 종류를 늘리는 작업보다 이 사용자 흐름의 완결을 우선한다.

### 4. 자료 링크에서 실제 발표 목록으로 전진 — 다음 순위

QQQ·SPY 화면에 연결할 공식 발표 목록과 상세의 공개 읽기 계약을 구현한다. 출처 URL, 발표 예정 시각과 한국 시간, 원문 이용 가능 시각, 갱신 상태를 표시한다. 자동 수집이 미완료라면 출처를 검증한 수동 등록임을 명시하고 가짜 날짜를 넣지 않는다. 권리 있는 과거 비교 수치가 없으면 자료 없음 상태로 두고 외부 차트를 자체 연구 성과로 설명하지 않는다.

### 5. 연구 평가와 제품 평가 분리 — 병행

이전 연구 인계 문서는 사용자 수요 확인까지 모델 HOLD 해제 조건에 섞어 적었다. 이번에 수정했다. 모델 성능은 사전에 정한 목표, 당시 사용 가능한 자료, 시간순 시험, 기준선 비교와 불확실성으로 판정한다. 제품 수요는 별도로 판정한다. 실제 평가 결과를 확인하지 못한 상태와 검증했으나 개선이 없는 상태도 구분한다.

TLT의 일봉 기반 미래 5·20거래일 변동성 결과를 QQQ·SPY의 가격 방향이나 FOMC 충격 예측 성과로 바꾸어 설명하지 않는다. 발표 전후 관측 비교와 미래 변동성 예측은 목표가 다르므로 실험·화면 이름도 분리한다. 연준 연구 방법을 도입할 때 원문·목표·빈도·동일 날짜 기준선을 확인한다. 이번 중간 평가는 새로운 논문 검토나 새 모델 실험을 수행한 것은 아니다. 첫 5거래일 정답 하나가 생겨도 모델의 유용성을 입증한 것은 아니다.

### 6. 열린 PR과 문서 누적 관리 — 상시

AI #11의 소유권을 현 설계에 맞게 정리하고, #12의 QQQ 수집을 연구 작업으로 분리한다. AI #13 웹 구현은 별도 웹 저장소로 이어졌으므로 신규 화면의 기준을 shockgraph-web으로 고정하고 중복 개발하지 않는다. #8~#10 연구·운영 PR은 충돌·의존성과 실제 필요성을 확인해 순서를 정한다. PR별 통과 시험 수를 합쳐 통합 품질로 계산하지 않는다. 이번 작업에서는 PR 병합·종료를 하지 않는다.

## 작업량과 객관적 평가

지금까지의 데이터 무결성·시점 검증과 채팅 신원 보강은 금융 개발 포트폴리오에 설명 가능한 내용이다. 반면 최근 화면 문구·경로 검사의 반복만으로는 공식 자료→종목→대화라는 핵심 가치가 완성되지 않는다. 개발 진행을 주도하면서 통합 경로보다 기반 검사와 작은 보완에 작업을 분산시킨 점을 수정해야 한다. 이후 한 작업의 완료 단위는 커밋 수나 시험 수보다 실제 사용자 기능, 실패 처리, 재현 가능한 증거로 정한다.

사업성은 아직 판단하기 이르다. 현재 화면은 공식 링크와 외부 차트 중심이어서 반복 방문할 이유를 입증하지 못했다. 초기 소수 사용자에게 다음 발표 찾기→관련 종목 자료 확인→근거를 붙인 대화라는 과제를 수행하게 하고 막힌 지점, 자료 이해 여부, 자발적 재방문을 관찰한다. 이 관측을 수익성이나 시장 전체 수요의 입증으로 확대하지 않는다.

이번 작업은 문서 평가·정정이다. 새 제품 기능이나 모델 성능 개선은 없다. 문서 1개 추가와 기존 문서 4개 수정을 수행했으며 코드 재시험을 했다고 보고하지 않는다. 기존 웹 코드의 시험 근거는 [커밋 3569285의 원격 검사](https://github.com/AnDev77/shockgraph-web/actions/runs/40822748097)다. 새 문서 변경의 링크·내용·차이 검사를 별도로 확인한다.
