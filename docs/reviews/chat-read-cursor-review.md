# 내 메시지 작성 후 다른 회원 글 누락 수정

기준일: 2026-11-11. 오늘 배포, 금요일 핵심 기능 완료의 사용자 결정에 따라 실제 채팅 경로를 점검했다.

## 시작

웹 main `f64feb8`, 열린 #3 `7e463c9` 확인. #3은 공식 발표 근거 화면이며 채팅 조회 수정과 중복되지 않는다. 기존 작업 트리를 보존하고 main에서 별도 작업 트리를 만들었다. Java 초안 #14의 원격 게이트는 성공했으나 운영 연결은 아직 미검증이다.

## 문제와 수정

마지막으로 읽은 글이 ID 1일 때 다른 회원이 ID 2를 작성하고 내가 ID 3을 작성하면, 기존 화면은 ID 3 작성 응답만으로 조회 기준을 3으로 바꿨다. 다음 목록 조회가 afterId=3부터 시작해 ID 2를 화면에서 놓칠 수 있었다. 이제 작성 응답은 내 글 표시만 갱신하고 목록 응답만 조회 기준을 전진시킨다. 다음 조회는 afterId=1로 ID 2와 ID 3을 함께 읽고 화면에서는 ID로 중복을 제거한다.

## 검증

신규 회귀 시험은 초기 목록→상대 글 존재→내 글 작성→다음 목록 조회→누락 없는 표시와 내 글 중복 제거→조회 기준 전진을 확인한다. 합성 API와 타이머 콜백으로 재현하며 실제 서버 시험이 아니다. 기존 코드에서 새 시험이 실패했고 수정 코드에서 성공했다. 로컬 타입/린트, 전체 18개 시험, 빌드, 정적 자산 2개/직접 URL 7개 검사를 통과했다. 로컬 Playwright 데스크톱/모바일 4개는 Chromium 실행 파일 부재로 시작 전 실패했다. 최종 커밋의 원격 브라우저 게이트를 따로 확인한다.

## 작업량과 한계

제품 코드 1개 수정, 회귀 시험 1개 추가, 현재 계획/AGENTS 정리와 이 리뷰다. 현재 React는 5초 간격 조회이며 STOMP 브라우저 구현이나 두 앱 간 방송 공유를 구현했다고 주장하지 않는다. 모든 DB 트랜잭션 커밋 순서 문제나 고부하 메시지 완전성을 이번 한 시험이 증명하지 않는다. 실 EC2 배포·메일·두 브라우저 인수·제품 수요·연구 성과는 별도다. 비공개 값은 포함하지 않았다.
