# 모바일 가입에서 종목방 글쓰기까지

- **시작 (2026-11-13 KST):** 웹 원격 main은 `f64feb8`이며, 조회 누락 수정이 담긴 열린 #4의 `86dec75`를 기준으로 분리했다. #5의 관심 목록 작업 트리는 수정하지 않았다. #4 이전과 달리 가입·로그인과 채팅 화면은 있지만, 글을 쓰러 로그인하면 처음 보던 방으로 돌아가는 링크가 없었고 목록 갱신이 전송 실패 표시를 지웠다.
- **변경:** QQQ·SPY만 계정 화면의 복귀 대상으로 전달한다. 목록 읽기와 글 쓰기의 오류를 나누고 목록 재시도와 글 내용 보존을 제공한다. 글을 재전송할 때 같은 내용이면 기존 요청 ID를 쓴다. 401·409·429와 잘못된 응답을 한국어로 안내한다.
- **검증:** TypeScript·ESLint, 합성 API 시험 전체 21개, 빌드, 산출물 2개와 직접 URL 7개가 통과했다. 목록 실패 복구, 글 실패 후 조회에 따른 안내 보존 및 동일 요청 ID, 잘못된 API 응답을 시험했다. Chromium은 로컬에서 소켓 생성 제한 때문에 실행 전에 종료돼 브라우저 검증은 GitHub CI에서 진행한다.
- **완료 기준과 남은 일:** 데스크톱·모바일에서 종목방→가입→로그인→같은 방 글쓰기 흐름을 합성 API로 확인한다. 주가 그래프는 변경하지 않았다. 실제 EC2 Java·MySQL·Redis·SMTP 연결 및 Vercel 환경 변수 설정은 별도다. 실제 메일과 두 브라우저 채팅이 확인되기 전에는 공개 가입과 채팅을 켜지 않는다.
- **원격 브라우저 중간 실패:** 이메일 입력 뒤 필수값 검사가 실패해 발송 요청 전 중단됐다. 입력값을 React 상태에 보관하고 키 입력으로 같은 흐름을 재검증한다. 최종 판정은 최신 커밋의 원격 결과를 따른다.
