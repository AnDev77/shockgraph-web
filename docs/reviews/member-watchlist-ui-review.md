# 회원 관심 종목 화면 연결

기준: 2026-11-12 한국 시간. 금요일까지 연구 성과 제외 핵심 기능 목표에 따라 Java 초안 #16의 회원별 관심 API를 React에 연결한다.

## 시작

- 원격 웹 main `f64feb8`; 열린 #3은 발표 근거 화면, #4는 채팅 읽기 커서 오류 수정이다. #4에서 분기해 중복 수정을 피했다.
- Java #16의 `GET/PUT/DELETE /api/v1/watchlist[/{symbol}]`는 원격 초안으로 이미 제안했으며 V2 테이블/권한 분리·두 이미지 격리 인수 검사를 진행한다. Java main과 운영 EC2에는 아직 없다.
- 기존 화면은 QQQ/SPY 차트와 종목방을 보여주지만 관심 등록·목록을 저장하지 않는다.

## 구현과 중간 검증

- 종목 상세에 로그인 안내/관심 추가·제거 버튼, 홈에 현재 회원의 관심 목록을 추가한다. 화면은 응답을 Zod로 검증하고 미승인 응답·네트워크 실패 시 저장 성공으로 표현하지 않는다.
- Java가 확인한 로그인 토큰만 보내며 회원 ID는 요청 본문·경로에 넣지 않는다. 계정이 바뀌면 이전 회원의 관심 종목을 숨기고 새 회원 목록 로드 전에 버튼을 잠근다.
- `VITE_WATCHLIST_ENABLED=true`일 때만 화면을 연다. `VITE_WATCHLIST_API_BASE_URL`은 브라우저가 접근할 HTTPS `/api/v1/watchlist` 주소다. 운영 Java 연결과 메일 가입 확인 전에 플래그를 켜지 않는다.
- 합성 시험은 익명 API 호출 부재, 가입 뒤 조회·추가·제거, Bearer 헤더, HTML/잘못된 종목/401 응답 거절, 장애 시 비활성 버튼, 두 계정 화면 격리를 확인한다. 실제 Vercel/EC2 연동 결과는 아니다.

## 검증 결과·한계

로컬 `npm run check`, 전체 시험 23개, 빌드·자산 2개/직접 URL 7개 확인을 통과했다. 로컬 Chromium 실행 파일은 없어 Playwright는 시작되지 못했으며, 최종 원격 브라우저 게이트를 따로 확인한다. 실제 두 브라우저와 EC2 API 결과는 별도다. 가입 뒤 새로고침 시 로그인 메모리 세션이 지워지는 현재 정책은 그대로다. 임의 종목, 목표주가, 뉴스, RAG/Agent는 본 기능의 범위 밖이다.

## 작업량과 오류

API 계약 1개, 재사용 화면 1개, 홈/종목 상세 연결, 합성 시험, 이 리뷰를 포함한다. 다른 실행의 미커밋 변경은 건드리지 않았다. 연구 성과와 사용자 수요는 이 UI 시험으로 입증하지 못한다. 비공개 가격·비밀값·미검증 성과 수치 없음.
