# 회원가입·로그인 연결과 배포 확인

## 연결 설정

회원 화면은 `/signup`, `/login`이다. 기본 빌드는 회원 기능이 비활성화돼 미연결 서버에 비밀번호를 보내지 않는다. 회원 서버가 준비되면 빌드 환경에 다음을 설정한다.

- `VITE_AUTH_ENABLED=true`
- `VITE_AUTH_API_BASE_URL=https://<승인된-Java-호스트>/api/v1/auth` 또는 동일 출처 프록시가 있으면 `/api/v1/auth`

`VITE_` 값은 브라우저에 공개되는 설정이다. SMTP 비밀번호나 JWT 서명키를 넣지 않는다. 운영에는 HTTPS를 사용한다. 기본 Vercel SPA rewrite만으로 Java API가 생기지 않으므로 프록시 또는 실제 Java URL이 필요하다. HTML 200을 API 성공으로 취급하지 않는다.

Java에는 `APP_AUTH_ALLOWED_ORIGINS=https://shockgraph-web.vercel.app`처럼 정확한 웹 Origin을 설정한다. SMTP는 `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM`과 공급자의 TLS 조건을 확인한다. 비밀값은 배포 환경의 비밀 저장소에서만 설정한다. 프록시 환경은 실제 사용자 IP 전달과 신뢰할 프록시를 확인한다. 임의 X-Forwarded-For를 그대로 신뢰하는 설정은 사용하지 않는다.

## 사용자 흐름

이메일 발송 → 코드 확인 → 10분 가입 증표 발급 → 증표를 포함한 가입 → 로그인 순서다. 이메일을 바꾸거나 인증 시간이 지나면 가입 증표를 폐기한다. 재발송·서버 제한 시간에는 대기 안내를 제공한다. 가입 실패 때 증표가 이미 소진됐을 수 있으므로 로그인 또는 재인증을 안내한다. 로그인 토큰은 메모리 세션에만 보관하고 새로고침·로그아웃·만료 시 다시 로그인한다. 로그인 성공이 관심 종목 저장이나 채팅 연결 완료를 뜻하지 않는다.

## 검증 종류와 남은 조건

- Vitest: 발송/확인/가입 계약, 이메일 변경, 실패 후 재인증, 429, HTML fallback, 로그인 실패·로그아웃, 증표 만료.
- Playwright: Chromium의 데스크톱과 모바일 에뮬레이션에서 가입→로그인→새로고침, 장애 안내 및 가로 넘침 검사. API 응답은 합성 fixture이며 실제 메일이나 Java 서버를 사용하지 않는다. 물리 모바일 기기 검증을 대신하지 않는다.
- Java PR #7: 실제 Redis와 MockMvc 계약 시험. 회원 DB·SMTP·토큰 발급기는 대역인 시험이므로 운영 통합 성공을 뜻하지 않는다.
- 배포 인수: 승인된 Java URL/DB/Redis, 실제 SMTP 수신, 두 브라우저, CORS, 잘못된/만료된 코드·토큰, 재발송·시도 제한, 장애 안내를 실제 환경에서 확인해야 한다.

화면을 공개할 수 있어도 실제 수신·운영 연동이 미확인인 상태에서 가입 기능을 활성화하지 않는다. 미확인 입력은 사용자 결정 분기점이며 그 밖의 코드·계약 시험은 계속 진행한다.
